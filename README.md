# monozukuri

English: [README.en.md](README.en.md)

レーザー加工・3Dプリントのデータ作成を手伝います。
Claude（Claude Code・Claude アプリ）ではプラグインとして、Codex などほかの AI ではスキルのフォルダとして導入できます。
寸法・はめあい・ファイル形式・材料の安全といった部分を主に補助し、アイディアの提案も行います。
**立体のモック → 確認ページ → フィードバック → 次の版** を繰り返して形を決めます。最終的にはFusion などで人が造形を行う想定です。立体のモックを版ごとに見比べながら、高速にアイディアを具現化できます。
## 入れ方

### Claude アプリ（デスクトップ・Web）

1. 左のサイドバーで **Customize** → **Plugins** を開く
2. **Add marketplace** を選び、`Pinticketaro/monozukuri` を入力する
3. 一覧に出た **monozukuri** を選んで **Install** を押す

マーケットプレイスを使わない場合は、[monozukuri.plugin](https://github.com/Pinticketaro/monozukuri/raw/main/dist/monozukuri.plugin) をダウンロードし、チャットに添付して追加することもできます。プラグインは有料プラン（Pro・Max・Team・Enterprise）で使えます。

### Claude Code（ターミナル）

```
/plugin install monozukuri --marketplace Pinticketaro/monozukuri
```

`/plugin` で始まるコマンドは Claude Code 専用です。Claude アプリの入力欄では使えません。

### Codex とほかの AI

Codex など、`~/.agents/skills/` からスキルを読む AI では、このリポジトリを置いて、3つのスキルのフォルダをリンクします。

```bash
git clone https://github.com/Pinticketaro/monozukuri.git ~/monozukuri-skills
mkdir -p ~/.agents/skills
ln -sf ~/monozukuri-skills/plugins/monozukuri/skills/monozukuri-* ~/.agents/skills/
```

- 3つのスキル（`monozukuri-setup`・`monozukuri-new-project`・`monozukuri-review-page`）は、同じフォルダに並べて入れてください。スキルどうしで参照資料とスクリプトを使い合います。
- `git pull` で新しい版になります。入れたら AI を起動し直してください。
- 前に monozukuri-codex（Codex 版）を入れていた場合も、上のコマンドで同じ名前のリンクがこちらに置き換わります。
- Codex では `$monozukuri-setup` のように `$` を付けて名前を書くか、`/skills` から選びます。依頼の文が説明に合えば、名前を書かなくても選ばれます。
- Windows では、WSL（Windows の中の Linux）の中で AI と上のコマンドを動かします（下の「対応環境」）。

## 対応環境

| 環境 | 使えるか | 要るもの・注意 |
| --- | --- | --- |
| macOS | 使えます | Python 3.10 以上と Node.js（`brew install python@3.12 node`） |
| Linux | 使えます | Python 3.10 以上、Node.js、日本語フォント（Ubuntu なら `fonts-noto-cjk`） |
| Windows の WSL（Ubuntu など） | 使えます（Linux として動きます） | AI も WSL の中で動かし、プロジェクトは WSL 側のフォルダ（`~/` の下）に置きます |
| Windows のまま（PowerShell） | まだ使えません | セットアップのスクリプトが動きません |

| AI | 確認ページ | 決めてほしいことの聞き方 | スキルの呼び方 |
| --- | --- | --- | --- |
| Claude Code | PC のブラウザ（`serve_review.py`） | 選択式の問いの画面 | `/monozukuri:monozukuri-setup` など |
| Claude アプリ | アーティファクトとして公開するか、PC のブラウザ | 選択式の問いの画面 | ふつうの言葉で頼む |
| Codex | PC のブラウザ（`serve_review.py`） | 文字で、番号付きの選択肢 | `$monozukuri-setup` など |

どの AI でも同じ SKILL.md を使い、プロジェクトのファイルの形（パラメータファイル、`out/vNN/`、`review/`）も同じです。ある AI で作ったプロジェクトを、別の AI で続けられます（アーティファクトに書かれたフィードバックは、Claude アプリからしか読めません）。

### Windows の場合

- **いちばん手軽なのは Claude アプリで使うことです**。レンダリングなどの処理は Claude のクラウドの作業環境（Linux）で動くので、Windows でも Mac と同じ手順で使えます。新しい会話のたびに「モックの環境を整えて」が必要です。
- **パソコンで直接動かすなら、WSL（Windows の中の Linux）の中で AI（Claude Code・Codex など）を使ってください**。
  1. PowerShell で `wsl --install` を実行し、Windows を再起動します（Ubuntu が入ります。管理者の権限が要ります）。
  2. Ubuntu の中に、使う AI（Claude Code か Codex）、Node.js、日本語フォント（`sudo apt install fonts-noto-cjk`）を入れます。Codex では、上の「Codex とほかの AI」のコマンドも Ubuntu の中で実行します。
  3. プロジェクトは Ubuntu 側のフォルダ（`~/` の下）に置きます。Windows のフォルダ（`/mnt/c/` の下）でも動きますが、ファイルの読み書きが遅くなります。
- **WSL を使わずに、Windows のまま（PowerShell）で使うことは、まだできません**。セットアップやレンダリングの途中で止まることが分かっています。
- Claude アプリでプロジェクトを PC のフォルダに置くときは、OneDrive で同期しない浅い場所（例：`C:\work\`）にしてください。同期中のファイルの書き換えや、長すぎるパスで失敗することがあります。

## セットアップ

1. **新しい会話を始める**：プラグインは会話の開始時に読み込まれます。追加する前から開いていた会話では使えません。
2. **「モックの環境を整えて」と頼む**：レンダリングに必要なものがそろい、テストレンダリングまで確かめます。

## 使い方

ふつうの言葉で頼めば、対応するスキルが動きます。Claude Code では `/monozukuri:monozukuri-setup`、`/monozukuri:monozukuri-new-project`、`/monozukuri:monozukuri-review-page`、Codex では `$monozukuri-setup` などと名前でも呼べます。

本番の前に4つの段階（ステージゲート）を通ります。うまくいかない理由を、時間と材料のかかる本番ではなく、モックや小さなテストピースで見つけるためです。そのための4つの手順を、AI が手伝います。

| 手順 | あなたがすること | 返ってくるもの |
| --- | --- | --- |
| 1. 伝える | 「スマホを立てる台がほしい」のように、作りたい物を言葉で伝える。中に入れる物があれば、その寸法も伝える | 大まかな形の 3D と、3Dビューで見られる確認ページ |
| 2. 見て直す | 確認ページを見て「もう少し低く」「穴を右に」と頼む。他の人に見てもらい、意見を書いてもらう | 直した次の版。前の版との比べ |
| 3. 小さく試す | 「テストピースを作って」と頼み、はめ込む部分だけを小さく印刷する・レーザーカットする。測った結果を伝える | 自分の機材でぴったり合う寸法（次から作る物にも使える） |
| 4. 本番をつくる | 確かめた寸法で本番を印刷する・レーザーカットする。仕上げを CAD でしたいときは「Fusion 用に出して」と頼む | 本番用の 3D データ。CAD で仕上げる人には寸法の一覧と STEP |

1と2を何度も繰り返して形を決めてから、3に進むのが基本です。チェックリストやスキルの中では、1・2を「モック」、3を「テストピース」「部分試作」と呼んでいます。

迷ったら「次は何をすればいい？」と聞いてください。プロジェクトのチェックリストを見て案内します。

## できること（v0.7.0）

| スキル | こう頼むと動く | すること |
| --- | --- | --- |
| monozukuri-setup | 「モックの環境を整えて」「Mac でレンダリングできるようにして」 | レンダリング・断面・比較に必要なもの（shapely、manifold3d、trimesh、networkx、cascadio、cadquery、playwright＋Chromium、three.js、日本語フォント）をまとめて入れ、テストレンダリングまで確かめる。Mac ではプロジェクトの外の仮想環境（`~/.monozukuri/venv`）に入れる |
| monozukuri-new-project | 「新しいものづくりを始めたい」「テストピースを作って」「ツールを更新して」「英語にして」 | パラメータファイル（形の寸法＋加工パラメータと信頼度）、モック生成（1つの形の定義から STL と STEP。STEP は本物の円弧・円柱・円錐を持ち、Fusion で部品ごとのコンポーネントとして開ける）、テストピースの生成、レンダリング・断面・比較・寸法表のスクリプト、段階チェックリスト、引き継ぎ資料、Git 設定のテンプレートを作り、最初のモックをレンダリングする。加工方法（レーザー／3Dプリント／両方）に合わせて加工パラメータと手順を絞り、3Dプリントでサポートが要りそうな面を自動で知らせる。プロジェクトの言語（日本語／英語）を決め、切り替える |
| monozukuri-review-page | 「この版の確認ページを作って」「フィードバックを読んで」「ブラウザで確認ページを開いて」 | モックや人が作ったモデル（STL / OBJ / STEP）をレンダリングして前の版と比べ、プロジェクトごとの確認ページに版を追加して、PC のブラウザで開く（Claude アプリではアーティファクトとしても公開できる）。ページに書かれたフィードバックと答えを AI が読み、反映したら返信や「決定」を付ける |

### 0.7.0 で変わったこと

- **スキルの名前が変わりました**：`setup` → `monozukuri-setup`、`new-project` → `monozukuri-new-project`、`review-page` → `monozukuri-review-page`。Claude Code での呼び方は `/monozukuri:monozukuri-setup` などになります。ふつうの言葉で頼む使い方は変わりません
- Codex など、ほかの AI でも同じスキルが使えます（上の「Codex とほかの AI」）。選択式の問いの画面が無い AI では文字の選択肢で聞き、確認ページは PC のブラウザで開きます
- PC で開く確認ページのサーバーは、AI のコマンドが終わっても動き続けます（以前は Claude Code で10分ほどで止まることがありました）。止めるときは「確認ページを止めて」と頼むか、`serve_review.py <プロジェクト> --stop`
- 今までのプロジェクトはそのまま動きます（ツールはプロジェクトの `tools/` に写してあるため）

### 0.5.0 で変わったこと

- 英語に対応。言語はプロジェクトごとに日本語か英語。チャットで「英語にして」と頼んで切り替える。確認ページ・図・パラメータファイル・文書も英語になる。ページに切り替えボタンは無い
- 英語で始めたプロジェクトは英語で作られ、文書のファイル名も英語になる（`docs/checklist.md` など）
- 今までのプロジェクトは何もしなくても日本語のまま動く。英語にするときは、プラグインを更新してから「ツールを更新して」と頼む（英語の図や表示は新しいツールで出る）

### 0.4.0 で変わったこと

- 平面図に真上から見た外形が重なり、断面の高さに無いラグや突起も見える。上面・正面の図に大きな影が出ず、ビューごとに枠いっぱいにレンダリングして縮尺の目安を入れる
- テンプレート：`--process`（レーザー／3Dプリント／両方）で加工パラメータを絞る。筒・円錐台・回転体・ストラップホール付きのラグの関数。3Dプリントでサポートが要りそうな面を notes に自動で出す
- 決めてほしいことを mock の notes に問いの候補として書くと、確認ページで はい／いいえ・案の選択で答えられる。足りない情報は番号で選ぶ画面で聞く
- 確認ページを Claude Code から PC のブラウザで開ける（フィードバックは `review/feedback_local.json` に残る）。公開のたびにエクスポート（downloads）を有効にし、使えない画面では「エクスポート」を押せない表示にする
- **既存のプロジェクトは、プラグインを更新したら「ツールを更新して」と頼む**（`tools/` はプロジェクトにコピーされているため。`mock.py` は上書きせず、新しいテンプレートを `mock.py.new` として置く）

### 確認ページでできること

- 版の切り替え（URL の末尾に `#v03` を付けるとその版が開く）
- 外観・平面図・断面図、前の版との比較スライダー、寸法の変化の表
- 3Dビューでモデルを見る（スマホでも）
- 見ている版の STL / STEP を ZIP でエクスポートする
- PC のブラウザで開ける（「ブラウザで確認ページを開いて」。Claude Code・Codex など）
- 「決めてほしいこと」に はい／いいえ や案の選択で答える
- フィードバック（直したい／良い／質問）を図や問いごとに書く

## 守ること

- **公開されている数値は初期値です**。カーフ・板厚・クリアランス・インサート穴は、テストピースで測った値に置き換えてから本番に進んでください。同梱の技術要件は出典ごとに【実測】【指針】【規格】【経験則】を区別していますが、どれも自分の機材での確認が前提です。
- **レーザーカットしてはいけない材料があります**。「この材料はレーザーカットしていい？」と聞けば確かめます。可否はラボ（レーザー加工機）ごとにも異なるので、所属ラボのルールを優先してください。

## AI の誤りへの備え

AI は、寸法の読み違い、単位の取り違え、資料にない数値をもっともらしく書くといった誤りをすることがあります。monozukuri は、誤りがあっても本番の前に見つかるように作っています。

**monozukuri がしていること**
- **寸法はパラメータファイルだけに書く**：モック・テストピース・寸法表・Fusion 用パラメータはすべて同じパラメータファイルから作るので、書き写しによる食い違いが起きません。
- **値ごとに状態と根拠を持たせる**：加工パラメータには「初期値」「実測」などの状態と、根拠（出典や測り方）が付きます。確かめていない値は「仮」や「初期値」と表示されます。
- **単位チェック**：モデルを読み込むたびに全体の大きさを mm で出し、不自然なら警告します。
- **レンダリングした画像を自分で確かめる**：モックをレンダリングしたら、AI が画像を見て依頼の形になっているかを確かめます。
- **人が見て直す**：確認ページで人に見てもらい、その意見を次の版に反映します。
- **物で確かめる**：本番の前に、テストピースと部分試作で実物の寸法とはめあいを確かめます。
- **戻せる**：版ごとに残し、Git で記録するので、前の版に戻れます。

**使う人にお願いしたいこと**
- 中に入れる物や既製品の寸法は、ノギスなどで実測して伝えてください。
- 気になる値は「この値の根拠は？」と聞いてください。根拠と資料を示します。
- 本番の加工の前に、テストピースか部分試作を一度は通してください。
- 材料の安全とラボのルールは、最後は人が確かめてください。AI の答えより、所属ラボのルールを優先してください。

## monozukuri がしないこと

- 最終の製造データを自動で作ること（最終形は人が CAD でモデル化します）
- 写実的な見た目を作ること（モックは形を決めるための粗い立体です）
- 作った物を使い始めた後の保守・修理の支援
- 似た部品を大量に、速く作ること（試行錯誤を楽しむためのプラグインなので、ほかのツールに任せます）
