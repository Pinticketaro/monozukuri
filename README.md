# monozukuri

English: [README.en.md](README.en.md)

レーザー加工・3Dプリントのものづくりで、**立体のモック → 確認ページ → フィードバック → 次の版** を速く回すための Claude プラグイン。
モックは形と比率を決めるための粗い立体で、最終形は Fusion などで人がモデル化する前提です。モデル化した結果（STL / STEP）も同じ確認ページで見比べられます。

## 入れ方

### Claude アプリ（デスクトップ・Web）

1. 左のサイドバーで **Customize** → **Plugins** を開く
2. **Add marketplace** を選び、`Pinticketaro/monozukuri` を入力する
3. 一覧に出た **monozukuri** を選んで **Install** を押す

マーケットプレイスを使わない場合は、[monozukuri.plugin](https://github.com/Pinticketaro/monozukuri/raw/main/dist/monozukuri.plugin) をダウンロードし、チャットに添付して追加することもできます。プラグインは有料プラン（Pro・Max・Team・Enterprise）で使えます。

### Claude Code（ターミナル）

```
/plugin install monozukuri --marketplace Pinticketaro/monozukuri
```

`/plugin` で始まるコマンドは Claude Code 専用です。Claude アプリの入力欄では使えません。

### Windows の場合

- **おすすめは Claude アプリで使うことです**。描画などの処理は Claude のクラウドの作業環境（Linux）で動くので、Windows でも Mac と同じ手順で使えます。新しい会話のたびに「モックの環境を整えて」が必要です。
- **パソコンで直接動かすなら、WSL（Windows の中の Linux）で Claude Code を使うのが確実です**。プロジェクトは WSL 側のフォルダ（`~/` の下）に置いてください。
- **Windows のまま Claude Code を使う場合**は、次をそろえてください（まだ十分に試せていません。うまく動かないときは Issue で教えてください）。
  - [Git for Windows](https://git-scm.com/downloads/win)（Claude Code がコマンドを動かすのに使う Git Bash が入っています。無いとセットアップが動きません）
  - Python 3.10 以上（python.org 版。インストール時に「Add python.exe to PATH」にチェック）と Node.js
  - `python3` が使えないときは、Claude に「python3 の代わりに python を使って」と伝えてください
- プロジェクトは、OneDrive で同期しない浅い場所（例：`C:\work\`）に置いてください。同期中のファイルの書き換えや、長すぎるパスで失敗することがあります。

## 最初に一度だけ

1. **新しい会話を始める**：プラグインは会話の開始時に読み込まれます。追加する前から開いていた会話では使えません。
2. **「モックの環境を整えて」と頼む**：描画に必要なものがそろい、テスト描画まで確かめます。

## 使い方の流れ

ふつうの言葉で頼めば、対応するスキルが動きます。Claude Code では `/monozukuri:setup`、`/monozukuri:new-project`、`/monozukuri:review-page` と名前でも呼べます。

本番で失敗しないように、先に画面の上と小さな試しで確かめておきます。そのための4つの手順を、AI が手伝います。

| 手順 | あなたがすること | 返ってくるもの |
| --- | --- | --- |
| 1. 伝える | 「スマホを立てる台がほしい」のように、作りたい物を言葉で伝える。中に入れる物があれば、その寸法も伝える | 大まかな形の 3D と、回して見られる確認ページ |
| 2. 見て直す | 確認ページを見て「もう少し低く」「穴を右に」と頼む。他の人に見てもらい、意見を書いてもらう | 直した次の版。前の版との比べ |
| 3. 小さく試す | 「試し片を作って」と頼み、はめ込む部分だけを小さく刷る・切る。測った結果を伝える | 自分の機械でぴったり合う寸法（次から作る物にも使える） |
| 4. 本番をつくる | 確かめた寸法で本番を刷る・切る。仕上げを CAD でしたいときは「Fusion 用に出して」と頼む | 本番用の 3D データ。CAD で仕上げる人には寸法の一覧と STEP |

1と2を何度も繰り返して形を決めてから、3に進むのが基本です。チェックリストやスキルの中では、1・2を「モック」、3を「試し片」「部分試作」と呼んでいます。

迷ったら「次は何をすればいい？」と聞いてください。プロジェクトのチェックリストを見て案内します。

## できること（v0.5.0）

| スキル | こう頼むと動く | すること |
| --- | --- | --- |
| setup | 「モックの環境を整えて」「Mac で描画できるようにして」 | 描画・断面・比較に必要なもの（shapely、manifold3d、trimesh、networkx、cascadio、cadquery、playwright＋Chromium、three.js、日本語フォント）をまとめて入れ、テスト描画まで確かめる。Mac ではプロジェクトの外の仮想環境（`~/.monozukuri/venv`）に入れる |
| new-project | 「新しいものづくりを始めたい」「試し片を作って」「道具を新しくして」「英語にして」 | 寸法ファイル（形の寸法＋加工の値と信頼度）、モック生成（1つの形の定義から STL と STEP。STEP は本物の円弧・円柱・円錐を持ち、Fusion で部品ごとのコンポーネントとして開ける）、試し片の生成、描画・断面・比較・寸法表のスクリプト、段階チェックリスト、引き継ぎ資料、Git 設定の雛形を作り、最初のモックを描く。作り方（レーザー／3Dプリント／両方）に合わせて加工の値と手順を絞り、3Dプリントでサポートが要りそうな面を自動で知らせる。プロジェクトの言語（日本語／英語）を決め、切り替える |
| review-page | 「この版の確認ページを作って」「フィードバックを読んで」「ブラウザで確認ページを開いて」 | モックや人が作ったモデル（STL / OBJ / STEP）を描画して前の版と比べ、プロジェクトごとの確認ページに版を追加して公開する（Claude Code では PC のブラウザで開く）。ページに書かれたフィードバックと答えを Claude が読み、反映したら返信や「決定」を付ける |

### 0.5.0 で変わったこと

- 英語に対応。言語はプロジェクトごとに日本語か英語。チャットで「英語にして」と頼んで切り替える。確認ページ・図・寸法ファイル・文書も英語になる。ページに切り替えボタンは無い
- 英語で始めたプロジェクトは英語で作られ、文書のファイル名も英語になる（`docs/checklist.md` など）
- 今までのプロジェクトは何もしなくても日本語のまま動く。英語にするときは、プラグインを更新してから「道具を新しくして」と頼む（英語の図や表示は新しい道具で出る）

### 0.4.0 で変わったこと

- 平面図に真上から見た外形が重なり、切る高さに無い耳や出っ張りも見える。真上・正面の図に大きな影が出ず、ビューごとに枠いっぱいに描いて縮尺の目安を入れる
- 雛形：`--process`（レーザー／3Dプリント／両方）で加工の値を絞る。筒・円錐台・回転体・ストラップの耳の道具。3Dプリントでサポートが要りそうな面を notes に自動で出す
- 決めてほしいことを mock の notes に問いの候補として書くと、確認ページで はい／いいえ・案の選択で答えられる。足りない情報は番号で選ぶ画面で聞く
- 確認ページを Claude Code から PC のブラウザで開ける（フィードバックは `review/feedback_local.json` に残る）。公開のたびに書き出し（downloads）を有効にし、使えない画面では「書き出す」を押せない表示にする
- **既存のプロジェクトは、プラグインを更新したら「道具を新しくして」と頼む**（`tools/` はプロジェクトにコピーされているため。`mock.py` は上書きせず、新しい雛形を `mock.py.new` として置く）

### 確認ページでできること

- 版の切り替え（URL の末尾に `#v03` を付けるとその版が開く）
- 外観・平面図・断面図、前の版との比較スライダー、寸法の変化の表
- 3Dモデルを回して見る（スマホでも）
- 見ている版の STL / STEP を ZIP で書き出す
- Claude Code では PC のブラウザで開ける（「ブラウザで確認ページを開いて」）
- 「決めてほしいこと」に はい／いいえ や案の選択で答える
- フィードバック（直したい／良い／質問）を図や問いごとに書く

### 言語

- 言語はプロジェクトごとに日本語か英語です。寸法ファイルの `meta.lang` に残ります。書かれていなければ日本語です。
- 切り替えるときは、チャットで「英語にして」「日本語に戻して」と頼みます。確認ページに切り替えボタンはありません。
- 英語のプロジェクトでは、確認ページ・図の文字・寸法表・試し片の手順書・文書が英語になります。部品名や寸法の名前は、書いたときの言葉のままです。

詳しくは [plugins/monozukuri/README.md](plugins/monozukuri/README.md)。

## 守ること

- **公開されている数値は初期値です**。カーフ・板厚・クリアランス・インサート穴は、試し片で測った値に置き換えてから本番に進んでください。同梱の技術要件は出典ごとに【実測】【指針】【規格】【経験則】を区別していますが、どれも自分の機材での確認が前提です。
- **レーザーで切ってはいけない材料があります**。「この材料はレーザーで切っていい？」と聞けば確かめます。可否はラボ（機械）ごとにも異なるので、所属ラボのルールを優先してください。

## AI の誤りへの備え

AI は、寸法の読み違い、単位の取り違え、資料にない数値をもっともらしく書くといった誤りをすることがあります。monozukuri は、誤りがあっても本番の前に見つかるように作っています。

**monozukuri がしていること**
- **寸法は寸法ファイルだけに書く**：モック・試し片・寸法表・Fusion 用パラメータはすべて同じ寸法ファイルから作るので、書き写しによる食い違いが起きません。
- **値ごとに状態と根拠を持たせる**：加工の値には「初期値」「実測」などの状態と、根拠（出典や測り方）が付きます。確かめていない値は「仮」や「初期値」と表示されます。
- **単位の関所**：モデルを読み込むたびに全体の大きさを mm で出し、不自然なら警告します。
- **描いた画像を自分で確かめる**：モックを描いたら、Claude が画像を見て依頼の形になっているかを確かめます。
- **人が見て直す**：確認ページで人に見てもらい、その意見を次の版に反映します。
- **物で確かめる**：本番の前に、試し片と部分試作で実物の寸法とはめあいを確かめます。
- **戻せる**：版ごとに残し、Git で記録するので、前の版に戻れます。

**使う人にお願いしたいこと**
- 中に入れる物や既製品の寸法は、ノギスなどで実測して伝えてください。
- 気になる値は「この値の根拠は？」と聞いてください。根拠と資料を示します。
- 本番の加工の前に、試し片か部分試作を一度は通してください。
- 材料の安全とラボのルールは、最後は人が確かめてください。AI の答えより、所属ラボのルールを優先してください。

## monozukuri がしないこと

- 最終の製造データを自動で作ること（最終形は人が CAD でモデル化します）
- 写実的な見た目を作ること（モックは形を決めるための粗い立体です）
- 作った物を使い始めた後の保守・修理の支援
