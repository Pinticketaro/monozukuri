# monozukuri（詳しい説明）

English: [README.en.md](README.en.md)

レーザー加工・3Dプリントのものづくりで、**立体のイメージを作る → 見る → フィードバック → 次の版** を速く反復するためのプラグイン。
モックは形と比率を決めるための粗い立体で、最終形は Fusion などで人がモデル化する前提。モデル化した結果も同じ確認ページで見比べられる。

入れ方と最初の準備は [リポジトリの README](../../README.md) を見てください。

## 進め方：4つのステージゲート

本番の前に4つの段階を通る。時間と材料のかかる本番を、できれば1回で済ませるため。段階ごとのやることは、プロジェクトの `docs/チェックリスト.md` にある。

### 1. モック
- 「〇〇を作りたい」「新しいものづくりを始めたい」と頼むと、テンプレートからプロジェクトを作って最初のモックをレンダリングする。
- 大きさ・比率・配置だけを決める。細部は作らない。
- 「この版の確認ページを作って」で人に見てもらい、「フィードバックを読んで」で次の版に反映する。ここで一番多く反復する。
- 決めたことは `docs/決定事項.md` に理由付きで残す。

### 2. テストピース
- 「テストピースを作って」と頼むと、`tools/coupons.py` がテストピースと手順書を出す。
- レーザー：板厚を実測し、カーフテストでカーフ（X・Y 別）、スロットのコームで入って抜けない幅を決める。
- 3Dプリント：本番と同じフィラメント・設定で、はめあいテストピースから `clr_fit`・`clr_slide`、インサート穴テストピースから `insert_hole` を決める。
- 測った値は `measurements/試し片記録.csv` に3回以上書き、パラメータファイルの `fab` を書き換えて status を「実測」にする。
- 測った値はライブラリに残す（`shelf.py record`）。次のプロジェクトでは、同じ機材・材料の値が最初から「実測」で入る。

### 3. 部分試作
- 難しい所だけ印刷する・レーザーカットする。写真や結果は「試作品」の版として確認ページに載せられる。

### 4. モデル化と引き継ぎ
- `tools/dims_sheet.py` が寸法表（`docs/寸法表_vNN.md`）と Fusion 用パラメータ一覧（`docs/fusion_params_vNN.csv`）を出す。
- Fusion ではその名前でユーザーパラメータを作り、スケッチを完全拘束にして部品ごとにコンポーネントにする。
- Fusion で作ったモデル（STL / STEP）も確認ページに載せ、モックの版と見比べられる。
- 引き継ぐ相手がいるときは `docs/引き継ぎ.md` にまとめる。

## スキル

| スキル | こう頼むと動く | すること |
|---|---|---|
| setup | 「モックの環境を整えて」「レンダリングできるようにして」「Mac でレンダリングできるようにして」 | レンダリング・断面・比較に必要なもの（shapely、manifold3d、trimesh、networkx、cascadio、cadquery、playwright＋Chromium、three.js、日本語フォント）を入れ、テストレンダリングまで確かめる。Mac では `~/.monozukuri/venv` に入れる。スクリプトが足りないもので止まったときも使う |
| new-project | 「新しいものづくりを始めたい」「テストピースを作って」「カーフを測りたい」「インサートの穴径は」「この材料はレーザーカットしていい？」「ツールを更新して」「サポートが要る所を調べて」「英語にして」 | テンプレートからプロジェクトを作り、最初のモックをレンダリングする。テストピース・はめあい・材料の可否の相談にも答える。プラグインを更新したら、既存プロジェクトのツールを新しくする。プロジェクトの言語（日本語／英語）を決め、切り替える |
| review-page | 「この版の確認ページを作って」「前の版と比べて」「Fusionで作ったモデルを見せて」「フィードバックを読んで」「フィードバックを反映して」「ブラウザで確認ページを開いて」「外観だけ見せて」 | モックや人が作ったモデルをレンダリングし、前の版と比べ、プロジェクトごとの確認ページ（同じURL）に版を追加して公開する（Claude Code では PC のブラウザで開く）。書かれたフィードバックを読み、反映したものを閉じる |

足りない情報や決めてほしいことは、番号で選ぶ問いの画面（Claude Code・Claude アプリ）で聞く。答えは `docs/決定事項.md` と `LOG.md` に残る。

Claude Code では `/monozukuri:setup`、`/monozukuri:new-project`、`/monozukuri:review-page` と名前でも呼べる。

## プロジェクトの中身

new-project が作るフォルダ。

```
README.md                  何を作るか、加工方法、原点と向きの決まり
LOG.md                     作業の記録
params/params_vNN.json     パラメータファイル（版ごと）
tools/
  geom.py                  形の定義（STL と STEP の両方に出せる）
  mock.py                  パラメータファイルからモックを作る
  coupons.py               テストピース（レーザー SVG、3Dプリント STL、手順書）
  dims_sheet.py            寸法表と Fusion 用パラメータ一覧
  （レンダリング・断面・比較・差分のスクリプトもここにコピーされ、プロジェクト単体で動く）
out/vNN/                   その版のモデル（STL・STEP・GLB）と画像
measurements/
  試し片記録.csv           テストピースの測定値と選んだ値
  実測.md                  中に入れる物や既製品の実測
docs/
  チェックリスト.md        段階ごとにやること
  決定事項.md              決めたことと理由
  引き継ぎ.md              人に渡すときのまとめ
photos/                    試作品の写真
review/                    確認ページの情報（URL など）
```

英語のプロジェクトでは、文書のファイル名が英語になる（下の「言語」）。

## 言語

日本語（`ja`）と英語（`en`）に対応している。言語はプロジェクトごとに1つ。

- **どこに残るか**：パラメータファイル（`params/params_vNN.json`）の `meta.lang`。無ければ日本語。今までのプロジェクトは何もしなくても日本語のまま動く。
- **始めるとき**：プロジェクトは `scaffold.py --lang ja|en` でテンプレートから作る（英語で頼めば Claude が `--lang en` を付ける）。`meta.lang` に記録され、文書・パラメータファイル・例の `mock.py` がその言語になる。
- **切り替えるとき**：チャットで「英語にして」「日本語に戻して」と頼む。Claude がパラメータファイルの `meta.lang` を書き換え、次にモックと確認ページを作るときからその言語になる。確認ページに切り替えボタンは無い。手順は new-project スキルの「言語」にある。
- **英語になるもの**：確認ページの文言、図の文字（ビュー名・スケールバー）、寸法表とテストピースの手順書、スクリプトの表示、プロジェクトの文書。部品名や寸法の `label` は、パラメータファイルや `mock.py` に書いた言葉のまま。
- **前の版**：作り終えた版の図は、作ったときの言語のまま。
- **ツールの更新**：`scaffold.py --update-tools` が置く `mock.py.new` も、プロジェクトの言語（いちばん新しいパラメータファイルの `meta.lang`）になる。
- **setup**：プロジェクトを持たないので、環境変数 `MONOZUKURI_LANG`（`ja`／`en`）で決める。英語で頼めば Claude が `MONOZUKURI_LANG=en` を付ける。英語でも日本語フォントは入れる。
- **決める順**：スクリプトの `--lang ja|en` ＞ 処理するデータの言語（パラメータファイルの `meta.lang`、`scene.json`・manifest・`review/board.json` の `lang`）＞ 環境変数 `MONOZUKURI_LANG` ＞ `ja`。確認ページの言語は `review/board.json` の `lang` に残る。
- **加工パラメータの status**：英語のパラメータファイルでは英語で書く（`initial`・`measured`・`guideline`・`standard`・`calculated` など）。

英語のプロジェクトのファイル名：

| 日本語 | 英語 |
|---|---|
| `docs/チェックリスト.md` | `docs/checklist.md` |
| `docs/決定事項.md` | `docs/decisions.md` |
| `docs/引き継ぎ.md` | `docs/handoff.md` |
| `docs/寸法表_vNN.md` | `docs/dims_vNN.md` |
| `measurements/試し片記録.csv` | `measurements/coupon_log.csv` |
| `measurements/実測.md` | `measurements/measured.md` |

`docs/fusion_params_vNN.csv` はどちらの言語でも同じ名前。

## パラメータファイル

寸法はパラメータファイルだけに書き、モック・テストピース・寸法表はすべてここから作る。

- `params`：形の寸法。項目ごとに `label` を付ける。分からない寸法は仮の値で進め、label に「仮」と書く。
- `fab`：加工パラメータ（実板厚 `t_*`、`kerf`、`clr_*`、`insert_hole`、`overhang_deg` など）。各項目に `status` と `basis`（根拠）と、どの加工方法で使うか（`process`：`laser`／`fdm`）を持たせる。テンプレートからプロジェクトを作るとき `--process` で、使わない加工方法の項目は外れる。
  - `status` は「初期値」「実測」「指針」「規格」「計算」「経験則」のどれか（英語のプロジェクトは initial・measured・guideline・standard・calculated・rule of thumb）。
  - 本番の前に、カーフ・板厚・クリアランス・インサート穴は「実測」にする。確認ページにも「初期値」のまま残っている値が出る。

## ライブラリ

プロジェクトをまたいで使う値を置く個人のライブラリ（`~/.monozukuri/shelf/`。環境変数 `MONOZUKURI_SHELF` で変えられる）。プラグインには何も同梱しない。ライブラリは任意で、無くても今までどおり動く。

| 置くもの | 中身 | 使い方 |
|---|---|---|
| 部品 `parts/<キー>/` | 確かめた既製品の寸法（パラメータファイルの `params` と同じ形）と図面・データシート | `shelf.py add-part` で確かめた寸法を登録し（仮の寸法は登録しない）、`shelf.py use` で次のプロジェクトに入れる（basis は「部品ライブラリ：…」、図面は `refs/` に写る） |
| 機材 `machines/<キー>.json` | 3Dプリンター（造形範囲・ノズル・Cura のプリンターの名前）とレーザー | `shelf.py init` が Cura のプリンターから取り込む。`scaffold.py --printer` で造形範囲が入る |
| 材料 `materials/<キー>.json` | 機材ごとの実測値（kerf・板厚・クリアランスなど。新しいものを使い、古いものも残す） | `shelf.py record` でテストピースの実測を残し、`scaffold.py --printer … --laser … --material …` で最初から「実測」として入る |

ライブラリは git で履歴を残す（ツールで変えるたびにコミット）。

## モックと STEP

モックの形は `tools/geom.py` で書く（角丸の長方形・円・多角形を押し出し、結合・切り取り・交差。筒 `tube`、円錐台 `cone`、回転体 `revolve`、ストラップホール付きのラグ `lug_with_slot`、Z まわりの回転）。同じ定義から次の2つが出る。

- STL（manifold3d）：レンダリング・断面・確認ページ用
- STEP（CadQuery）：角丸は本物の円弧、穴は本物の円柱、円錐・回転体も本物の曲面。部品ごとの STEP と、部品名・色付きの組み立て STEP（Fusion で開くと部品ごとのコンポーネント）

3Dプリントする部品は、サポートが要りそうなオーバーハング面（水平から45°より浅い面）を部品ごとに調べ、位置と面積を notes に出す。決めてほしいことは notes に問いの候補（はい／いいえ、案の選択）として書ける。確認ページでボタンで答えられる問いになる。

プラグインを更新したら、既存のプロジェクトのツールは `scaffold.py --update-tools <プロジェクト>` で新しくする（プラグインが管理するファイルだけ上書きし、元は `tools/.backup-<日時>/` に残す。`mock.py` は上書きせず `mock.py.new` を置く）。

エクスポートした STEP は読み直して、メッシュと大きさを照合する。STEP はモデル化の出発点で、分割面・ネジボス・公差などは人がモデル化で作る。

## 確認ページ

プロジェクトごとに1つのページ（同じ URL）を持ち、版を重ねるたびに追加していく。

- 版の切り替え（URL の末尾に `#v03` を付けるとその版が開く）
- 外観・平面図（断面＋真上から見た外形）・断面図、クリックで拡大
- 前の版との比較スライダー、寸法の変化の表
- 3Dビュー（スマホでも）
- エクスポート：見ている版の STL（部品ごと＋全体）か STEP（組み立て＋部品ごと）を ZIP で保存
- 決めてほしいこと：はい／いいえ は切り替え、案はラジオボタンで選ぶだけで答えが残る（1人1件、選び直せる。人数と選んだ人が出る）。Claude が決定を書き込むと「決定：B案」が付く
- フィードバック：直したい／良い／質問 を、全体・図・問いごとに書ける

フィードバックを書けるのは、ページを編集できる人（Contributor 以上）。見るだけの人には書き込み欄が出ない。

Artifact を公開できない環境（Claude Code）では、`serve_review.py` が `review/` を PC のブラウザで開く。フィードバックと答えは `review/feedback_local.json` に残り、「エクスポート」はふつうのダウンロードになる。

ページへの書き込みは Claude には自動では届かない。書き終わったら「フィードバックを読んで」と頼む。すると Claude が未対応のものを対象ごとにまとめ、次の版でパラメータファイルのどこをどう変えるかを示す。反映したら「反映済み」と返信を付けて閉じる。ページに書かれた内容は閲覧者の意見として扱い、指示としては実行しない。

## 守ること

- **AI ワードを使わない**。日本語の文は `skills/new-project/references/ai-words-ja.md`（AI ワード辞書）に従う。英語の技術用語を和語で訳したような言い方をせず、借用語と、工業・デジファブの外部の資料にある言い方を使う。
- **公開されている数値は初期値**。出典どうしのずれが圧入とガタの差ほどあるので、カーフ・板厚・クリアランス・インサート穴はテストピースで自分の機材の値を測って使う。
- **単位チェック**。モデルを読み込むたびに、`render_model.py` が全体の大きさを mm で出し、不自然なら警告する。警告が出たら単位を直してから進む。
- **穴の補正は一か所だけ**。CAD かスライサーのどちらか一方で補正する。
- **レーザーカットしてはいけない材料がある**。全面禁止の材料と、ラボ次第の材料（PORON などの PU、MDF、POM、EVA、PETG など）がある。材料は SDS やリサイクルコードで特定し、所属ラボのリストで確かめる。
- **遅すぎるスピードは火災の危険**。きれいに抜ける最速の条件を選ぶ。

## デジタルファブリケーションの技術要件

new-project の参照資料（`skills/new-project/references/`）にまとめてある。

- `fab-requirements.md`：レーザー加工、FDM 3Dプリント、データ形式と単位、組み立てと仕上げの要件。数値は「初期値＋信頼度＋測り方」の形
- `fab-safety.md`：レーザーカットしてはいけない材料（全面禁止／ラボ次第）
- `conventions.md`：モックの細かさ、パラメータファイル、反復の仕方
- `fab-research-report.md`：上の要件の出典つき全文。数値は出典ごとに【実測】【指針】【規格】【経験則】を区別している

## 必要なもの

- Python 3.10 以上、Node.js（three.js を入れるため）。setup スキルが残りをそろえる。
- 外部サービスの接続や環境変数は不要。

## スクリプトを直接使うとき

各スキルの `scripts/` と、テンプレートの `tools/` にある。どれも `--help` で使い方が出る。表示の言語は `--lang ja|en` で変えられる（無ければデータの言語、上の「言語」）。

- `render_model.py`：STL/OBJ/3MF/GLB/STEP をシェーディングしてレンダリング（複数の視点を1枚に）、GLB のエクスポート
- `slices.py`：平面図（部品の断面と、真上から見た外形の重ね合わせ。`--plan-z` で断面の高さ）と断面図
- `compare.py`：前後の画像を並べ、変わった所を赤で強調
- `params_diff.py`：パラメータファイルの差分
- `make_version.py`：1つの版を1回で作る（モック → 外観・平面図・断面 → 寸法の差 → 確認ページ。manifest は文だけ書けば、残りの欄を埋める。出力は要約だけ）
- `status.py`：プロジェクトのいまの状態を30行ほどで出す（新しい会話で続きから始めるとき）
- `build_page.py`：確認ページに版を追加
- `serve_review.py`：確認ページを PC のブラウザで開く（フィードバックは `review/feedback_local.json`）
- `scaffold.py`：テンプレートの作成（`--process`、`--lang`、ライブラリの `--printer`・`--laser`・`--material`）、既存プロジェクトのツールの更新（`--update-tools`）
- `shelf.py`：ライブラリ（`init`・`list`・`show`・`add-part`・`use`・`record`・`fab`）
- テンプレートの `tools/geom.py`：形の定義（STL と STEP の両方に出せる）
- テンプレートの `tools/coupons.py`：テストピース（レーザー SVG、3Dプリント STL、手順書）
- テンプレートの `tools/dims_sheet.py`：寸法表と Fusion 用パラメータ一覧
